项目定位与架构

单机优先的桌面素材库
图库 TuKu 是面向 Windows 桌面单机创作者的素材管理工具，对标 Eagle 4 的交互与能力， 在系统级桌面集成、编辑产出、大库性能上做得更重，不追账号体系与云同步。 数据全部落在本地库目录，素材文件与数据库同目录管理，可离线、可迁移、可版本快照。 工程质量按「能不能自己发现错误」衡量：四套 tsconfig 类型闸 + electron 逐文件真检查 + 293 条单测 + 97 项冒烟， npm run verify 一条命令跑完，CI 跑的是同一套脚本。

技术栈与类型闸

  • 桌面：Electron + 主进程 / utilityProcess（服务单属主）
  • 服务：Express 5 + node:sqlite，只绑 127.0.0.1
  • 前端：React + TypeScript + Vite；App.tsx 拆成 8 个 hook，本体 1716 行
  • 图像：sharp、纯 JS 元数据分析、CLIP/ONNX Runtime
  • 类型：Web / Node / 纯函数库 / server-lib 四套 tsconfig；electron/、server/lib、server/routes 逐文件 @ts-check 且由 lint 守门
  • 分发：electron-builder 26 + NSIS + electron-updater

数据组织

  • 多资源库各自独立 gallery.db
  • 库数据放 .tuku 点目录（文件出口须 dotfiles: allow）
  • 设置按库隔离；微博 Cookie / 代理 / AI 配置跨库共享
  • 全量哈希 + pHash 互补去重，CLIP 向量落磁盘分桶索引

规模目标

  • 目标百万级素材：worker 池 + 批量事务 + 单次解码 + 增量扫描
  • 百万行 HTTP 接口实测 10/10（标签列表 797→4ms、统计缓存 p95 2504→4ms）
  • bench:quick 15/15 达标并接入 verify；CI 上绝对时延门槛放宽 3 倍只拦数量级回退
  • 验收看吞吐与 API p95，不看单张图导入耗时

        CI 与更新通道

        触发行为
        push main / 手动先跑 verify，通过后 Windows 打包、更新固定 tag rolling 的预发布（旧资产不累积）
        push v* tag建正式 Release（make_latest: true），产物 TuKu-Setup-*.exe + latest.yml
        客户端自动更新electron-updater 只读正式 Release 的 latest.yml，rolling 预发布不推给用户
        失败取证verify 失败把 verify-out.txt 推到 ci-logs-verify，打包失败把 build-out.txt 推到 ci-logs；匿名 API 读不到 Actions 日志，只能走分支
        双远程origin → GitHub（SSH）、gitee → Gitee（凭据已存），两边都要推

        发版标准流程

        1npm version patch --no-git-tag-version 升版本号
        2npm run verify 全绿 → git add -A && git commit
        3git tag vX.Y.Z → git push origin main vX.Y.Z → git push gitee main vX.Y.Z
        4本地 npm run dist 出包，验 asar 内容与隔离启动
        环境与打包坑位（已踩过，勿重复）：
        ① electron-builder 必须 26.x，25.x 的依赖收集器会漏 call-bind-apply-helpers；CI 必须显式 --publish never，否则缺 GH_TOKEN 直接失败。
        ② asarUnpack 新增原生模块时，要把它运行时的纯 JS 依赖一并 unpack，否则用户机 require 不到。
        ③ 本地打包前确认 Get-Service ZhuDongFangYu 为 Stopped（360 主动防御会锁 default_app.asar），并清理 dist/ 残留；守卫环境下 builder 内部 rm 会被拦。
        ④ 国内网络设 ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/；离线可把缓存 zip 解到 .electron-dist 并用 --config.electronDist 跳过下载。
        ⑤ 打包版启动秒退先查单实例锁（共用 userData），用 --user-data-dir=<临时目录> 隔离验证。
        ⑥ 推送 tag 不要用 --tags：本地陈旧的 rolling 会让整条命令 exit 1，要点名推具体 tag。

        口径与维护

        分数来源：本项目基于当前代码与 npm run verify 实测；Eagle / Pixcall / Billfish 闭源，依据官网与 2026 年公开评测，误差约 ±3 分；Immich / PhotoPrism 依据公开对比。总分是加权平均，不是功能计数。

        跨类别慎比：Immich / PhotoPrism 是照片库，Eagle / Billfish / Pixcall 是素材库。总排名只作参考，判断看维度行。

        权重是假设：通用权重给跨端 11 分、个人单机给 0 分，对应两种用户结构。桌面单机创作者看单机口径（本项目 8.93 第一，Eagle 8.17）才是真实体感。

        本轮分数变化：「工程与文档」8 → 8.5，依据是 electron / server / routes 全部进入真类型检查并有 lint 守门、单测 293、冒烟 97、CI 失败可回传日志。其余维度未动，避免用文档给自己加感情分。

        本页怎么更新：按代码复核差距是否落地 → 改矩阵分数 → 移动「本轮完成」与「路线图」条目 → 勾掉遗留待办 → 「导出快照」存 docs/benchmark-YYYY-MM-DD.json。所有改动只存本浏览器（键 tuku.overview.2026-11-09.v1）。

        文档收敛：本页合并了原先的「竞品对标 11-08 / 11-09」与「遗留待办总表 11-06」，三份带日期的历史 HTML 已删除。以后只维护这一份，别再按日期新建副本。
