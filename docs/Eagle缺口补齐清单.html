3别乱改：这些你比 Eagle 强

  • 版本历史（versions 表 + 回溯预览）—— Eagle 没有。
  • 长图拼接、水印工作室、OCR、反向搜图、动态壁纸—— Eagle 要么没有，要么得装插件。
  • 纯本地 CLIP 语义搜索 + 偏好闭环—— Eagle 的 AI 依赖外部 API。
  • 多资源库 + 三道闸（库代数 / 根前缀 / .library 排除）—— 比 Eagle 的单库更工程化。
  • HTML 画廊与数据出口（CSV/JSON/zip）—— Eagle 导出能力弱。
判断标准：如果某个「对齐」改动会让上面任一项退化，那就是走错方向了。

4顺带看到的工程风险

  • 巨型文件：App.tsx 72KB、api.ts 68KB、Lightbox.tsx 66KB、WatermarkStudio.tsx 43KB —— 改一处要读整屏，继续按 hook 拆。
  • 197 个端点 / 21 个 route 文件，没有版本前缀也没有统一校验层 —— 一旦开放 API 就再也改不动，先定 /api/v1 再发布（与 EAGLE-03 相关）。
  • 运行期错误 typecheck 抓不到（上一轮白屏就是 TDZ 类问题）—— 面板级组件统一套 ErrorBoundary，并补一条「每个面板能挂载且不抛错」的冒烟。
