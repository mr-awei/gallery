01

Summary: first on local, and the long-term target also reaches first

Answer first, evidence second. The three parts answer: why it is first for standalone use, how many points each long-term goal is worth, and how to read these scores.

Why it ranks first on local

  • The data model is a "library" rather than an "album": 36 tables, 15 triggers, 30 indexes (foreign keys already handle cascades), an FTS5 trigram full-text index; 11 kinds of design files, 40+ RAW formats, 9 3D formats, and EPUB e-books can all enter the library and produce thumbnails.
  • Automation is native: 10 capture sources, 11 MCP tools, a plugin sandbox, token- and scope-based REST; /api/docs auto-generates 414 endpoints plus curl/JS/Python examples — peers usually offer only "import + drag".
  • Desktop integration reaches the system layer: tray, remappable global hotkeys, Windows live wallpaper (WorkerW + GLSL), drag-out to Explorer, right-click capture, and read-only LAN sharing.

How many points each long-term goal is worth (multilingual delivered)

  • Cloud and multi-device 15 → 80 (weight 9): accounts and read-only multi-device first, then incremental sync and mobile; delivers +5.85.
  • Collaboration and community 20 → 60 (weight 8): comments, sharing, and a least-privilege workflow; no commitment to a plugin marketplace; delivers +3.20.
  • Multilingual 5 → 90 (weight 5): delivered in 1.2.23, +4.25 already counted in the current score.
  • Cross-platform 20 → 85 (weight 4): mac hardware smoke test + installer, Linux deferred; delivers +2.60.
  • The remaining three total +11.7: 75.5 → 87.1, moving from 3rd to 1st. The order and prerequisites are in section 09.

In one sentence

If you are one person, one Windows machine, one local library of tens of thousands to hundreds of thousands of items, it is currently the best choice for value and controllability; these four platform capabilities are directions it genuinely intends to build, but the order is set by real constraints—a solo project, no server budget, single-platform maintenance cost— so do not expect them "in the next release".

Good for now: personal designer libraries / photography post-production asset pools / asset collection and archiving / workflows that need to be driven by scripts and AI.
Missing for now: team sharing, cross-device sync—they are on the roadmap, not in today's installer.
Three tiers, all on a 100-point scale, and with the same denominator (17 dimensions, 100 points of weight): ① 75.5 = now (multilingual delivered at 90, the other three counted at today's progress, 3rd); ② 80.6 = mid-term goal (read-only multi-device + real Mac hardware + permission prototype, 2nd); ③ 87.1 = long-term goal (the three counted at target values 80 / 60 / 85, 1st). The three tiers are monotonically increasing: 75.5 → 80.6 → 87.1, so the long-term goal cannot be lower than now. There is also another ruler: standalone-specific 90.8 (13 dimensions, 100 points, counting only implemented capabilities, used to compare the "local manager" with competitors). Its denominator excludes the 26 points of platform weight not yet delivered, so 90.8 and 87.1 cannot be subtracted directly—under the same basis the equivalent figure is 75.5.
Reading the scale: above 90 = close to the commercial ceiling in this class; 80–90 = mature and shippable, only polish left; 70–80 = usable but clearly behind the leaders; below 60 = a structural gap that patches cannot fix. This audit (2026-11-19) differs from the previous version (2026-11-16) in two substantive fixes: ① the collage save will-download async bug is fixed (Electron sync events cannot use an async handler, which stacked the default blank dialog on top of ours) — a P1 bug removed; ② competitor Eagle 4.0 B22 (2026 Q4) shipped the AI Search plugin + Web API v2, lifting Eagle's AI dimension from 65 to 72 and slightly improving automation; Immich v3.4.0 (2026-11) broadened ML v2 GPU coverage; PhotoPrism enabled NVIDIA CUDA for all models in 2026-10; ③ multilingual support shipped (1.2.23): UI / tutorials / tray / backend errors / plugin metadata / docs are all bilingual, 4,681 strings, moving the multilingual dimension from 5 to 90 (+4.25 on the current 17-dimension score). ④ This round (1.2.29) completes the capture inbox, color-label filtering, the infinite canvas and metadata CSV round-trip; these fill feature gaps without inflating dimension scores. Scoring method: 13 dimensions count the present, 4 platform capabilities count separately

Lay out "how it is computed" first, and the scores become worth discussing. All dimensions are scored directly on 100 and then weighted: the first 13 form the standalone baseline (100 points, counting only implemented capabilities); the last 4 are long-term platform capabilities (multilingual delivered at 90), each computed once at "today's value" and once at "target value", yielding 75.5 and 87.1. Weighting is "dimension score × weight ÷ 100" summed, so every point lost in a dimension costs 0.02–0.09 points overall.

Why the weights are set this way

  • Local baseline assumes one machine, one library, one user. What decides the daily experience is then "can I find it again quickly"—organization at 10 points plus retrieval at 12 points are the highest weights of all, followed by performance at 9.
  • Long-term 17 dimensions assumes that one day it must be compared with products like Immich that can "hold an entire team". In that case sync and collaboration total 17 points, multilingual and cross-platform 9 points, and the first 13 are diluted to 74—the four dimensions give 75.5 at today's progress and 87.1 at target values.
  • Both schemes give no credit for slideware: the AI dimension requires on-device execution and a fallback on failure; the performance dimension requires reproducible benchmark scripts.

How the scores are kept from drifting

  • Every point for TuKu can be re-checked: either a code location or a measured number from npm run bench:quick (15/15 passed on 2026-11-19).
  • Competitor scores are estimates based on public feature surfaces, not official vendor data. Within a tier they do not exceed 93 unless there is reproducible measurement.
  • When uncertain, score low: Eagle's AI capability, for example—in public materials AI Search is a "plugin" rather than a native pipeline, so it gets 72 rather than 85.
  • All 8 competitors are scored with the same questionnaire and the same set of anchors, avoiding "nitpicking rivals while going easy on ourselves".

The real advantages: ten things others don't do

This section lists only advantages traceable to code or measured numbers. Subjective items such as "nice experience" or "good-looking UI" are excluded.

01The broadest capture surface in its class

10 web capture sources, plus folder watching, ZIP, clipboard, drag-and-drop, browser right-click and phone upload — enough entry points to pick by "where I saw the image"; new assets can also land in the inbox for a single review pass before filing.

Evidence: server/crawler.js SOURCES table · extension/ · resumable capture writes to the jobs table

02The organization model is a "library", not an "album"

Eight views—folder tree, tag tree, collections, bookmarks, playlists, people, places, and timeline—share one index, so an asset can belong to several dimensions at once without duplicating files.

Evidence: server/db/schema-sql.js 36 tables / 15 triggers / 30 indexes (foreign keys handle cascades)

03Retrieval runs four paths in parallel, not four buttons

FTS5 trigram lets Chinese substrings match too; semantic search covers "I remember the image but forgot the words"; color and similar-image search cover "I want the same kind of thing". All four result sets can be stacked within one set of filters.

Evidence: measured keyword search 12ms, tag filtering 12ms, /api/tags 5ms (library of ~20k items)

04AI runs entirely on-device

Chinese CLIP semantics, ONNX face detection, HNSW nearest neighbors, local zero-shot tagging—no API key, no uploads, works offline.

Evidence: server/clip.js · lib/hnsw.js · lib/face-math.js; 20k vector search measured at 48 ms

05Automation interfaces are part of the product

REST with token and scope, 11 MCP tools callable directly by AI clients, and plugins that pass a manifest permission allowlist before entering the node:vm sandbox.

Evidence: server/mcp-server.mjs · lib/plugin-host.js · lib/plugin-manifest.js

06Desktop integration reaches down to the system layer

Tray, remappable global hotkeys, launch at startup, single instance, drag-out to Explorer, right-click capture, and Windows live wallpaper (WorkerW + GLSL).

Evidence: electron/main/ · wallpaper auto-pauses after fullscreen detection · the will-download async bug fixed this round

07Data is not locked in

Bidirectional XMP sidecars, CSV/JSON/HTML export plus metadata CSV import, verified backup and restore, trash, dual undo/redo stacks (200 steps / 2 GB), and read-only LAN sharing with password and expiry.

Evidence: lib/undo.js · lib/lan.js · backup scheduling lib/backup-schedule.js

08Editing is non-destructive, and it reconciles

Crop, rotate, color grading, erase, upscaling, watermark, and collage are all written as a edit_ops operation sequence, leaving the original untouched; the color preview and the final output match pixel for pixel.

Evidence: routes/edit* · undo uses the same operation stack · measured 16ms for 720p color grading / 70ms for 1600px

09There are real quality gates

DTO contract 47/54 in sync, 573 unit tests, 152 smoke tests, 15 benchmarks, plus four typecheck configs and one lint pass (275 files); npm run verify runs it all in one command.

Evidence: package.json scripts · scripts/verify* · CI and release share the same pipeline (all passed on 2026-11-19)

10Awareness of scale is built into the implementation

Import uses a worker pool plus batched transactions, lists paginate by keyset rather than deep offset scans, thumbnails are cached in tiers, and vector search uses an index instead of a full table scan.

Evidence: bulk ingest 5,428 rows/s (measured); list first page p95 6 ms, deep page 7 ms; CLIP 20k in 48 ms

Cloud & multi-device · weight 9

Now 15 → long-term target 80 (+5.85). Today is not zero: LAN read-only sharing (password / expiry / download disabled), backup to any cloud drive or removable disk, switching between multiple libraries.

Why long-term: the only one of the three that requires ongoing spend—servers, bandwidth, storage, backups, billed monthly. A solo project has no such budget, and should not promise data-safety responsibility before it can afford it.

Delivery path: read-only multi-device first (view on phone/web, no writes) → accounts and incremental sync → conflict merging. The read-only stage alone can reach about 50.

Pass criteria: the same account sees the same assets on two devices; offline reading works; conflicts raise a clear notice rather than a silent overwrite

Collaboration & community · weight 8

Now 20 → long-term target 60 (+3.20). What works today is export packages + read-only share links; the plugin system can host small internal tools, but nobody has written any yet.

Why it is long-term: collaboration presupposes accounts, permissions, and change history — all three live in the cloud item. Doing collaboration first means building half the cloud, in the wrong order.

Delivery path: annotations on share links → member roles (view/edit/manage) → approval flows. No commitment to a plugin and template marketplace: an empty marketplace hurts more than none.

Pass criteria: two accounts have different permissions on the same collection, and every change leaves an operation record

Multilingual · weight 5

Now 90 (delivered) → long-term target 90.1.2.23 completed: all interface copy extracted into strings (4,681 each for zh-CN / en-US), built-in tutorials bilingual, tray and native dialogs following the interface language, backend errors and task progress returned per Accept-Language, plugin metadata and runtime logs bilingual, and both HTML docs bilingual and switchable.

Why do it first: it is the only one of the four that needs no server and no budget; the cost is concentrated in the large-scale mechanical work of "extracting tens of thousands of strings, translating them, then freezing them"—worth doing alongside a refactoring window.

The 10 points still missing: configuration display names (AI provider / model / capture source labels) are still in Chinese; logs inside plugin packages are not localized; RTL languages are explicitly unsupported.

Pass criteria: no hardcoded Chinese remains after switching to English; dates, numbers, and units are formatted per locale

Cross-platform · weight 4

Now 20 → long-term target 85 (+2.60). Only Windows is validated today; mac / Linux have build targets but no real-hardware CI, so no support is claimed.

Why it is long-term: desktop integration (live wallpaper, drag-out, hotkeys, file associations) is implemented per platform, and three platforms means three maintenance burdens; without real hardware there is no "support".

Delivery path: item 2 in section 08 is its prerequisite — run 152 smoke tests on real Macs → installer and notarization → platform difference list; Linux follows.

Pass criteria: tray/hotkeys/drag-out/file associations all work on mac, with CI records kept
Why these scores are labeled "target values": a target value is an acceptance line, not a pledge. Lower any single item by 1 point and the 17-dimension total drops 0.4–0.9 (× weight ÷ 100); you can verify it in the table.

Why cross-platform comes before cloud and collaboration: cross-platform is a one-off project, costs no budget, and stays fixed once done (multilingual was finished first on this logic in 1.2.23); the latter two are recurring spend (servers + bandwidth + backups + on-call), which is also the real financial boundary of a solo project. So the roadmap states it plainly: finish the work that costs nothing first, then let revenue decide how far the cloud goes—this is a trade-off, not a capability problem.
10

Interoperability and "taking your data with you": an underrated advantage

The biggest hidden cost of an asset management tool is "three years in, you want to switch and cannot". This item carries only a small weight in the scoring, but for real users it may be decisive.

Two-way metadata

XMP sidecar read and write, so tags, ratings, and descriptions can be left for the next tool to read; originals stay originals, and edits only write an operation sequence. Evidence: server/lib/xmp.js · test/xmp.test.mjs 26 entries · edit_ops operation stack

Verifiable backups

Backup scheduling (daily/weekly), SHA256 verification for every file, and verification again on restore before writing. Backups can go to a cloud drive or a removable disk. Evidence: server/lib/backup-schedule.js · integrity.test.mjs · lib/integrity.js

Three export forms

CSV / JSON / HTML galleries, including offline single files with embedded thumbnails; CSV can also be edited and imported back (matched row by row by id / path, only present columns overwritten); Eagle import, folder flattening and tag_meta preservation all work. Evidence: server/routes/export.js · server/lib/transfer.js · galleryExport.test.mjs · server/lib/gallery-html.js

Clipboard and system-level

Drag out to Explorer/WeChat/PS/PPT; Ctrl+C copies a PNG straight to the clipboard; LAN read-only sharing with password and expiry. Evidence: electron/main/ipc-app.js drag-out · lib/lan.js · preload.cjs bridge

Dual undo/redo stacks

200 steps / 2GB cap, so any change can be rolled back; deletions go to the recycle bin rather than being erased immediately. Evidence: server/lib/undo.js · test/trash.test.mjs · trash-restore.test.mjs

Scriptable

Three REST scopes (read/write/ingest), 11 MCP tools, plugin sandbox; the whole library can serve as a data source for AI clients. Evidence: server/mcp-server.mjs · routes/docs.js · lib/plugin-host.js
