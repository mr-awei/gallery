01评估边界：为什么重做评分

旧版评分把「云同步、社区、协作」算进通用维度，于是「没做云」被扣分 —— 可云本来就不在预算与定位里。扣分项与产品目标不一致，分数就失去指导意义。这次只评本地管理器该做好的事，且每一维都要能在代码或实跑数据里找到证据；找不到证据的能力按 0 计。

纳入评分

  • 收集 → 组织 → 检索 → 编辑 → 导出这条主线
  • 本地 AI（人脸 / 语义 / OCR）与离线可用性
  • 自动化与开放接口（插件 / API / MCP / 扩展）
  • Windows 桌面与系统集成
  • 性能、数据安全、工程质量、交付与文档

不计分（附理由）

  • 云同步 / 社区 / 多用户：要服务器与账号体系，明确不做
  • 移动端原生 App：用「扫码投送 + 局域网只读浏览」替代
  • 在线素材市场：无运营与审核能力
  • 订阅与商业化：与目标无关

替代能力（局域网分享、同步文件夹、备份）只按「桌面便利性」计分，不折算成云能力。

06优势：真正拉开差距的十件事

下面每条都能在代码里指到位置，不是宣传语。

#优势证据与为什么它值钱
1本地优先、完全离线无账号、无服务端依赖；人脸/语义/OCR 全在本机跑，断网可用。Eagle 需要登录，PhotoPrism/Immich 需要常驻服务器 —— 这条是产品定位的根，不是功能点。
2检索栈有纵深FTS5 trigram（server/db.js）解决中文分词，短词回退 LIKE；再叠 CLIP 向量与 RRF 融合、系统 OCR、前缀语法（tag: / rating: / ext:）。多数同类产品只有「文件名 + 标签」。
3非破坏编辑 + 可回滚编辑走编辑链而非覆盖原图，edit_history 保留原图副本（2GB 配额）。同类开源项目普遍直接写回或只存 sidecar。
4桌面集成最全静态/动态壁纸、屏保、托盘、全局热键、文件关联、局域网投送与只读分享（server/routes/share.js）。Eagle 完全没做系统集成，digiKam 只做了文件关联。
5自动化是「可撤销的自动化」Actions 支持条件触发、预演（dry-run）与整体撤销；插件跑在独立子进程并带 5s 超时；/api/v1 有 scope 分级与审计；还提供 MCP server。Eagle 的插件体系更成熟，但没有 HTTP API 与 MCP。
6性能被当成可验收的指标scripts/bench.mjs 15 项门槛（列表 5ms / 深页 8ms / 搜索 11ms）、worker 池 + 批量事务，灌库 6431 行/秒。大多数个人项目只有「感觉挺快」。
7数据可恢复链条完整WAL + synchronous=NORMAL、schema_migrations 版本化迁移、回收站、库-盘对账、备份即文件夹拷贝（百万级不炸内存）。
8安全是按威胁模型写的server/auth.js 开头就写清威胁模型；timingSafeEqual 比较、Sec-Fetch-Site 拦跨站、query token 只允许只读、扩展 origin 白名单、登录限流与审计。这类项目常见的是「本地嘛，无所谓」。
9测试与守门成本低431 单测 / 133 冒烟 / 15 基准，npm run verify 一条命令串起来；冒烟会真的起服务、灌库、丢文件看监听。这轮发现的 4 个真 bug 全是被这条链子逼出来的。
10能力标注诚实插件「白名单不是沙箱」写在 README；语义没命中会明确降级；插值不叫超分。对本地工具来说，可信度本身就是体验。

08提分方案：先修「便宜的致命项」

排序原则：先做「成本低、影响面广、且能同时抬高多个维度」的项。预估增益按「维度分提升 × 权重 ÷ 100」计算，全部做完约 +0.42 → 9.13；但更重要的是用户能直接感知的三件事：大库不卡、键盘能用、备份敢删。

10明确不做的四类事

不做，以及为什么

  • 云同步：要服务器、带宽与账号体系，成本与维护都是无底洞；同步文件夹 + 手动备份已经能覆盖 90% 场景。
  • 社区 / 素材市场：需要审核、版权、举报与运营，不是一个人的项目该碰的。
  • 多用户与协作：权限模型、冲突合并、审计会推翻现有单用户数据模型。
  • 移动端原生 App：上架、签名、审核、双端同步都要持续投入。

用什么替代

  • 局域网投送 + 只读分享：手机/平板浏览器扫码看图、下载，不依赖公网。
  • 同步文件夹：把素材根目录放进 OneDrive / Syncthing / 局域网共享，由系统层负责同步。
  • 导出与互操作：CSV / JSON / HTML 画廊，随时能带走数据。
  • 备份：本地文件夹拷贝（百万级友好），建议配一块外置盘。

这条边界要写进 README 与产品页：「本地优先」不是缩水版，而是取舍后的产品主张。用户知道你不做云，就不会因为「没有手机自动备份」而失望；反过来，含糊其辞才会带来差评。

11互操作：数据能不能带走

方向支持度说明
从 Eagle 迁入支持可读取 Eagle 库结构与元数据；这是目前最重要的迁入路径。
迁出到其他 DAM部分只有 CSV/JSON 与文件本体；没有 XMP sidecar，Lightroom / digiKam 读不到标签与评分。P1-11 就是补这个。
备份可搬支持库就是文件夹，拷到别的机器可直接用；无账号绑定，这点优于 Eagle。
开放接口支持/api/v1 + scope + MCP，可被脚本与其他工具调用。
格式无损编辑部分编辑结果落在自己的编辑链里，不写回原图是优点；但副作用是外部工具看不到编辑结果，导出后才可交换。

13一句话结论

这是一款能力面比定位更宽的本地管理器：检索、自动化、桌面集成已经超过 Eagle，但多格式、细节打磨与跨平台还差一口气。 接下来的重点不是「再加功能」，而是把已经有的东西做扎实：大库不卡、键盘能用、备份可验证、数据能带走。 这四件事做完，8.71 会变成 9.1，而且每一条用户都能立刻感觉到。
