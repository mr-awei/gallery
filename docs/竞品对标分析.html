5功能扩展路线图

P0 高优先级（差异化、投入产出比最高）

  • MCP 原生壁纸控制：把壁纸/图库操作暴露成 MCP server，让 AI 助手直接"换张邓紫棋的 live 图""切到有山的壁纸"。你已有 OpenAI 兼容 AI，这是最独特的差异化入口（对标 wayper，但叠加粉丝主题）。
  • 标签 + 智能文件夹：基础标签、文件夹标签继承、按条件自动归类。补齐图片管理最大短板（对标 Eagle）。
  • 多显示器独立壁纸：每块屏不同壁纸/播放列表（对标 Lively / bigzhuodan）。

P1 中优先级（体验完整度）

  • 检索增强：以图搜图、颜色搜索、AI 语义/视觉搜索（复用现有 AI）。
  • 屏保模式 + 系统托盘常驻 + 快速切换/暂停。
  • 交互参数滑块：亮度/速度/强度/景深（Lively "IT'S MAGIC"）。
  • 壁纸类型扩展：网页/HTML、GIF、音频可视化（音乐律动）。
  • 重复项检测 + 评分/收藏/注释完整体验。
  • 本地偏好模型：用标签/评分/收藏训练个性化推荐，dislike/ban 反馈闭环（对标 wayper）。

P2 低优先级（生态与长尾）

  • 着色器/GLSL 壁纸、游戏引擎壁纸。
  • 浏览器插件采集（拖拽/批量/截图/一键高清）。
  • 主题包导出导入 + 粉丝社区分享（邓紫棋主题包很适合做卖点）。
  • 云同步 / 多端（Google Drive 等）。
  • AI 插件（去背景/超分/擦除）。
  • 挂载守护 + 崩溃自恢复（补回看门狗的健壮版，避免父窗口翻转）。
  • 丰富暂停策略：锁屏/电池/GPU 占用阈值/指定 App 前台。

7结论与建议

你项目在 「动态壁纸挂桌面层 + 本地落盘 + AI 知识库」 上已建立护城河；与 Wallpaper Engine / Lively / Eagle / wayper 相比， 最大洼地是 图片管理深度 与 AI→壁纸的闭环。

建议行动顺序：

  1. 先做 P0 三项（MCP 控制 + 标签/智能文件夹 + 多显示器）——它们彼此独立、见效快、且能形成"AI 驱动的主题壁纸管理器"独特定位。
  2. 再补 P1 体验（搜图/屏保/托盘/参数滑块/偏好模型），把"能用"变成"好用"。
  3. 最后做 P2 生态（主题包/云同步/着色器/守护进程），构建传播与留存。
差异化一句话：「会听你说话、懂邓紫棋、能自己挑图的桌面壁纸」 —— 这是 Wallpaper Engine 与 Eagle 都做不到的组合。
