# 手工验证脚本（不在 CI 里跑）

这些脚本是当初排查具体界面问题时写的一次性脚本，需要本机已启动开发环境、并且装了
`agent-browser` 才能跑；有些还依赖真实图库样本数据或已下载的模型，因此**交互结果不能
在 CI 里自动跑**。以前它们散在 `scripts/` 根下、没有任何 npm 脚本引用，看起来像自动化
测试的一部分，实际谁都不会执行。

现在 `npm run verify` 末尾会跑 `npm run verify:manual`（`scripts/verify-manual.mjs`）：
检查登记清单是否齐全、每个脚本能否被 Node 解析、README 是否还在，并把运行命令打印出来。
新加的 `.mjs` 若没登记进 REGISTRY 会告警，避免又出现「谁都不会执行」的孤儿。
**这只保证脚本可用，不代替手工点一遍**：交互断言仍需按下面命令自己跑。

留在这里是为了需要复现旧问题时还能找到，不要再往这里加新脚本。

需要自动化验证的话请看：

- `npm run verify`：eslint + 三份 tsconfig 类型检查（含 `tsconfig.lib.json` 的 checkJs）+ 单测 + `scripts/smoke.mjs`（真起服务）+ 手动脚本登记检查
- `scripts/smoke.mjs`：接口冒烟，断言安全头、鉴权、核心读写

注意：`verify-live.mjs` 里的 `C:\missing.mp4` 是故意写的不存在路径，用来验证
「保存视频壁纸配置时不真的去挂载文件」，不是笔误。

## 第三轮（T-22 ~ T-30）需要人工点一遍的项

这些是浏览器 / Electron 桌面层 / 手机 / 音频设备相关的能力，单测与冒烟只覆盖到接口契约，
不假装交互已经验证过。请起 `npm run dev`（桌面能力用 `npm run desktop`）后逐项确认：

1. **视频裁剪**：打开一段 5s 以上的视频 → 展开「首尾裁剪 / 导出 GIF」→ 拖起止滑块、勾「循环预览区间」、点「保存区间」；分别导出 GIF 与 WebM，用看图/播放器打开确认时长、首尾、颜色正确；超长片段（>120 帧）确认抽稀后播放速度没有变快。
2. **开放 API**：用主令牌调 `/api/v1/status` 与 `/api/v1/openapi.json`；在用户数据目录写 `api-tokens.json` 配一个只读令牌，确认能读、写接口回 403；连打超过 120 次确认 429。
3. **插件宿主**：设置 → 插件，试运行内置 `tag-prefix`；复制该目录到用户插件目录并改 `index.js`，确认动作编辑器的「插件脚本」步骤能批量打标签；把 `plugin.json` 的 `entry` 改成 `../` 开头的路径，确认被拒绝且主进程不受影响。
4. **手机扫码投送**：设置 → 手机投送开启，用手机扫二维码上传一张照片；换一台设备确认旧令牌轮换后旧二维码失效；关闭后确认端口不再监听。
5. **屏保 / 动态壁纸**：设置空闲为 1 分钟，等屏保出现后动一下鼠标确认立即退出并回到原桌面；全屏播放视频时确认不触发。
6. **GLSL / 交互 / 音频**：依次切到四种画面，确认帧率稳定、自定义 GLSL 编译错误会在桌面上显示、交互模式鼠标能驱动粒子且 Esc 恢复穿透、音频频谱随音乐变化、静音时画面仍在动但没有外放。
7. **实时滑块**：拖动亮度 / 速度 / 强度 / 景深，确认壁纸**立刻**变化且窗口没有闪屏或重新挂载；松手后重启应用确认设置保留。

## 第四轮（T-31 ~ T-36、T-38 ~ T-39）需要人工点一遍的项

单测与冒烟只覆盖到接口/纯函数契约，以下桌面层与站点行为必须起 `npm run desktop` 实测：

1. **暂停策略**：开一个游戏或全屏播放器，确认动态壁纸暂停、退出后恢复；把 GPU 阈值调到 5%，确认 GPU 忙时暂停；把 `notepad.exe` 填进「指定 App」，切到记事本确认暂停、切走恢复。GPU 计数器不可用的机器应看到规则被跳过而不是一直暂停。
2. **持续挂载守护**：重启 `explorer.exe`（任务管理器 → 重新启动 Windows 资源管理器），确认壁纸窗口被重新认领后 30 秒内自动回到图标层后面且不闪屏。
3. **网页壁纸**：默认填 `http://192.168.1.x/` 应被拒绝；打开「允许本地 / 内网」后能加载；`file://` 页面只有在可信目录内才允许，目录外的直接拒绝。关闭点击穿透后网页能点，按 Esc 立即恢复穿透，重启后设置保留。
4. **采集源**：分别只勾 Wikimedia / 豆瓣 / 贴吧各跑一次完整采集；豆瓣/贴吧被反爬时任务日志必须给出具体原因，而不是「0 张」悄无声息。
5. **擦除修复**：打开图片工具箱 → 擦除修复，涂一小块水印后写回，确认撤销能还原；大图（4000px 以上）确认耗时可接受且未擦除区域不变。
6. **主题包**：A 导出含图片的包，B 导入，确认配色、壁纸设置、图片目录都还原；把一个含 `url(...)` 的假包导进去，确认被过滤且界面没被注入。
7. **云同步**：两台机器（或本机两个用户数据目录）指向同一个同步文件夹，A 发布、B 拉取并切到新库；第二次发布应提示「0 字节跳过」；两端都改过后拉取应明确报冲突。
8. **跨平台**：在 macOS / Linux 上启动应用，确认图库浏览、采集、设置都能用，动态壁纸开关会明确回滚并提示；静态「设为壁纸」在对应桌面环境下真的换图（失败时列出尝试过的命令）。

## 第五轮（对照总表复核）需要人工确认的项

1. **只读令牌**：在用户数据目录 `api-tokens.json` 配一个 `read` 令牌，用它 `PUT /api/settings` 应回 403；`GET /api/v1/status` 仍 200。
2. **离线横幅**：让服务连续崩溃进入 dead 态，横幅应显示失败原因，点「立即重启服务」能恢复接口（不要再只靠托盘右键）。
3. **安装失败计数**：连续两次安装失败后，设置 → 壁纸 → 应用与更新应显示次数与「清零计数」，清零后强制更新策略恢复。
4. **视频导出**：故意用一段编码异常的视频触发录制超时，确认导出会报错结束而不是无限转圈；保存裁剪区间后重新打开视频，应从起点播放、到终点暂停。
5. **音频壁纸静音**：勾选静音后频谱应静止（以前还在跳）。
6. **主题包**：导入一个含 `url(...)` 配色 / 带分号的字体名的假包，确认界面没被注入；导入正常包后屏保、定时切换、暂停策略等设置都应还原，且本机路径不被带进来。
7. **同步冲突**：A 发布 → B 拉取 → B 改一张图 → A 再发布 → B 拉取应报冲突；把 manifest 里两条文件都改成 `gallery.db` 应被拒。
8. **采集 0 张**：只勾豆瓣或贴吧跑一次采集，被安全验证拦下时任务日志应写明原因，而不是只有「候选 0 张」。

改动 `server/**` 或 `electron/**` 之后必须重启应用才会生效。
